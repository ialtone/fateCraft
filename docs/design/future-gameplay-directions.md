# 后续玩法方向

性质：长期备忘。当前已经接入的八种类型和九个内容包见[玩法模块架构](24-gameplay-module-architecture.md)，具体范围见[制作指南](gameplay-modules/README.md)。生存探索、经营建设、潜入逃脱、关系叙事、古墓探险、地牢远征、宗门经营已有最小完整实现，修仙飞升下两包的深度规则修复仍在进行。

## 可继续扩展的方向

| 方向 | 当前基础 | 仍需新增 |
| --- | --- | --- |
| 大型城市经营 | 设施、生产、订单、库存 | 人口、政策、城区与长期供需模拟 |
| 独立案件推理 | 公开事实、NPC、互斥事件与关系 | 证据关联、嫌疑推演与可信指控规则 |
| 卡牌构筑 | 平台动作、版本和奖励 | 牌组、手牌、能量、回合与效果计算 |
| 战棋策略 | 角色、物品、有限遭遇 | 格子、单位、行动点、范围和先攻 |
| 航海探索 | 远征地图、补给与撤离 | 船只、航线、船员、海况与海战 |

这些方向不是当前迭代承诺，也不因已有相似字段就自动具备完整玩法。

## 扩展方法

同一模块支持的数值、地点、资源、角色或剧情变化，应优先通过固定版本内容完成；独立状态语义、新算法或新的结束循环需要编译安装可信模块。一个包只选一个主模块，公共组件在代码中组合，不提供管理员任意模块混搭或上传脚本的入口。

通用平台不新增 `RequiresRealm` 等题材分支。各模块直接输出自己的受众投影与可用行动，未知版本、动作或渲染器明确拒绝，不通过降级掩盖不支持的能力。确有共性时提取组件，避免模块互相导入后删除不适用的字段。

## 新方向的完成要求

1. 正常循环、失败路径、终局、状态、成本与时间有清晰规则。
2. 目录、Schema、引用、动作权限、资源来源和预算校验完整。
3. 至少一份可导入的完整示例与一份只改配置的变体。
4. 玩家行动和管理发布支持加载、冲突、失败与重试。
5. 回合事务、并发、随机证据、恢复、奖励和直连语义得到验证。
6. 正式文档明确本地结果与真实数据库、浏览器、模型待验项。

具体接口与现有测试可直接复用[24](24-gameplay-module-architecture.md)，不再另建第二套插件协议。
