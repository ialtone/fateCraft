# 26. 玩法结局、玩家确认与恢复

## 结局依据

结局由可信玩法动作、领域状态和固定版本 Outcome 决定。聊天中的“此世终”、自述飞升、确认文字或历史奖励记录不会直接结束对话，也不会生成结局窗口。自动成功、寿尽、死亡、超时由动作事务结算；玩家专属终局需要界面确认。

八类玩法的提前退出由模块声明 `AbandonAction`；共用运行时的退出动作必须 `Ending=true`、只授权 `player`、零参数。发布时执行各出身的初始退出探针，检查立即结束、不推进时间、对应启用的零积分 neutral Outcome。旧 Campaign 适配器检查动作注册和 allowlist；平台不按题材猜测退出动作。普通状态玩法没有可信退出动作时沿用普通关闭；绑定可信玩法的对话禁止绕过模块直接关闭。

## 主动终止与积分

提前终止保留已到账阶段积分，不发通关/终局积分，不将修为、资源或游戏时间兑换成离场积分。单局百年飞升劫只有成功飞升才能得分，提前终止为 0。客户端直连仍执行可信条件和结局，按现有规则停发玩法积分，并显示原因。

百年飞升劫新增 `trial.abandon`，结局为 `abandoned`，表示提前中止而非死亡。`trial.pass_away` 仍要求剩余寿元不超过五年，结局为 `peaceful_passing`；不会为了响应聊天中的坐化要求放宽条件。雷劫进行中仍可主动中止。青河修仙志使用 `campaign.abandon`，活动遭遇也不阻止玩家中止。最终任务由通用任务动作提交；只有完成真实飞升门槛后，模块才把对应任务方案公开为玩家终局提议，普通任务仍按原权限执行。

## 模型提议与确认

公开模型投影带有有界的 `ending_capabilities`，只包含玩家可见的终局描述、条件、修订、参数 Schema、方案、成本和拒绝原因。这是只读目录，不是模型执行权限。

Chat Completions 与 Responses 使用相同的 `fc_propose_ending` 工具：`action_key` 限于当前终局目录，`arguments_json` 为不超过 4096 字节的对象字符串。服务端在工具事务内重算玩家预览，校验参数与公开方案，返回 `ending_proposed`，持久化到原有 Agent 工具记录，广播 `ending.proposed`。它不改玩法状态、不扣资源、不发积分、不关闭对话。

页面展示待确认入口或条件不足原因。玩家可取消；确认弹窗说明成本、耗时和风险，通过现有模块玩家动作端点提交原分支和修订。条件再次变化时拒绝旧请求，不自动替玩家换成新修订执行。提议恢复只读取当前分支最新有效回合，过期修订不显示；本会话内暂不执行的提议不会因刷新反复出现。

终局目录和当前事实约束置于历史之后。提议成功仅表示入口已创建，模型不得据此宣称已死亡、通关或获积分。这个协议约束结构化操作；真实模型仍可能写错自由正文，本地协议测试不代表任意叙事的准确率。

## 统一结果与原子提交

`CompletionView` 统一承载 Challenge/Campaign 结局：`id`、`conversation_id`、`branch_epoch`、`revision`、`key/category/title/tone/summary`、实际 `rewards`、`metrics`、`next_actions` 和 `rewards_disabled_reason`。ID 由结算/动作身份、分支和终局修订构成。Campaign 奖励使用真实账号奖励字段，不伪造 Challenge run ID；指标显示保留的已到账阶段积分。

结果保存在现有模块动作、Campaign 动作或 Agent 工具结果中，没有新建结局表或迁移。Campaign 领域终态与关联 conversation 的 `ended/ended_at` 在动作提交事务中同步；Challenge 沿用原有结算事务。失败整笔回滚，提交成功后才广播 `challenge_completed.completion`。HTTP 玩家动作响应、WebSocket 和恢复查询消费同一个结果。

`GET /conversations/:id/endings` 校验所有权，返回当前分支/修订、终局目录、退出动作、提议、完成结果和生成中标记。恢复只读取当前有效分支、未失效回合中的已提交结果；不从正文或账号余额推断结局，也不重算奖励。普通 `conversation_ended` 仅同步生命周期，不能代替完整结局结果。

终局提交后的模型只允许同 turn/attempt/revision 的有限收尾；失败可继续叙事，不能重放动作或重复结算。旧生成任务和普通 ended 会话不能获得写入权限。

## 前端交互与重试

顶栏中止、行动面板和提议确认共用玩家动作请求日志。结果不明时保留 `request_id/branch_epoch/expected_revision/key/arguments`，提供“查询原请求”，重发相同 ID 获取幂等结果，不静默替换为新动作。已提交结果先更新结局与生命周期，再刷新历史、状态、余额；刷新失败说明展示未刷新，不误报动作失败。

重复 HTTP/WS 通知只显示一次窗口，关闭后会话内记录已读；刷新/重连可以恢复结果，顶栏“查看结局”可再次打开。会话切换使旧请求作用域失效，旧响应不能更新新会话或弹出旧结局。生成中禁止确认；事件与权威活动快照的按需对账共同刷新生成标记。sessionStorage 不可用时仍有内存去重，但浏览器完全刷新后的已读状态无法保留。

## 验证边界

本地检查与待验项见 [玩法模块验证](gameplay-modules/validation.md)。维护者应新建会话验证：年轻角色请求坐化→条件不足及中止提议→确认→数据库终态→正确窗口→普通生成不可继续；同时测试合法坐化、带参数成功终局、自动死亡/超时、双路通知、断线重查、取消与切换会话、直连零奖励以及终局后叙事失败。历史错误正文不做修复。

## 玩法包交换与版本管理

旧局继续原版结局校验和积分；发布、回退和解除暂停不复活已结束游戏。暂停期间原已提交动作/结局收据可查询；新提交被数据库策略栅栏拒绝，账号积分不回档。

完整协议见 [27 玩法包交换与版本生命周期](27-gameplay-package-exchange-and-versions.md)。
