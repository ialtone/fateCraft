# 03. 产品功能与权限

## 认证与账号

### 角色与首次安装

平台角色固定为三个：`owner`（唯一的平台拥有者）、`admin`（日常运营管理员）和 `user`（普通用户）。普通邮箱注册创建 `user`；LinuxDo 必须先绑定到已有站内账号，不会因为“第一个用户”而自动提权或创建账号。

空数据库处于首次安装状态时，普通注册暂不开放；部署者打开 `/setup` 安装向导，设置用户名和密码，可选填写邮箱，并明确确认这个新账号成为唯一 `owner`。成功后安装入口关闭，普通注册恢复。普通注册需要单独填写登录用户名（2-32 个字符，不含 `@`、空白和控制字符，大小写不敏感唯一），昵称可选，留空时使用用户名。`owner` 可在用户管理页授予或撤销 `admin`，后端事务阻止唯一 owner 被停用、删除或降级。

### LinuxDo 登录

LinuxDo Connect 是绑定到站内账号后的登录方式。后端使用 OAuth 2.0 Authorization Code + PKCE：创建短期登录 flow、跳转授权页、校验 state、交换 token、读取用户资料。登录 flow 只接受已经绑定的 subject；用户必须在设置页主动发起绑定，未绑定的 LinuxDo 账号不会自动创建站内用户。管理员在独立的“第三方账户”页面只能审计绑定关系，不能代替用户完成 OAuth 绑定。

是否启用 LinuxDo 登录由管理员开关控制（`auth_settings.linuxdo_login_enabled`，默认开启）；实际可用还需要部署环境变量配齐 Client ID/Secret/回调地址。关闭后登录入口隐藏，已发起的登录流程也无法完成，但不影响已有的绑定关系。两种登录方式允许同时关闭（之后无人能再登录，已有会话过期前仍有效）；仅关闭密码登录时，会检查 LinuxDo 可用且当前 owner 已绑定，避免把 owner 锁在站外。

外部 access token 不作为 Fatecraft 会话使用。登录完成后，服务端创建独立随机会话令牌，浏览器只持有 HttpOnly Cookie，数据库只保存令牌 SHA-256。

### 邮箱登录与注册

邮箱界面始终保留登录和注册入口，实际能力由数据库中的管理员设置控制：

- 本地密码登录：是否允许已有用户名或邮箱账号使用密码登录。
- 邮箱注册：是否允许创建邮箱账号，默认关闭。
- 邮箱验证码：注册前是否必须验证邮箱所有权。
- 邀请码：注册前是否必须消费一个有效邀请码。

这些限制由注册服务强制执行，不能通过伪造前端请求跳过。密码和验证码使用 bcrypt 摘要；验证码有有效期、重发间隔、5 次尝试上限并在注册事务中一次性消费。邀请码由管理员生成，可设置备注、最大使用次数、过期时间和启停状态，原文只显示一次，数据库只保存 SHA-256 摘要，名额在创建用户的同一事务中扣减。

SMTP 主机、端口、安全模式、用户名、发件地址、发件人名称和验证码模板由管理员维护。SMTP 密码使用 `AUTH_DATA_ENCRYPTION_KEY` 做 AES-GCM 加密，读取设置时只返回 `has_smtp_password`，不返回密文或明文。LinuxDo Client Secret 和加密主密钥仍属于部署环境变量，不进入管理页面。

### 会话

- 默认有效期 14 天，由 `AUTH_SESSION_TTL` 配置。
- 退出登录会删除服务端会话并清除 Cookie。
- 用户被禁用、会话过期或令牌不存在时，受保护接口返回未登录。
- Cookie 在 HTTPS 生产环境必须启用 `Secure`。

## 挑战发现与创建

普通用户登录后可以：

- 查看所有 active 且有当前发布版本的挑战。
- 查看挑战名称、简介、版本、标签、功能、快速指南和公开奖励概要。
- 查看该版本允许选择的 Persona 名称和公开描述。
- 选择挑战与 Persona，填写可选标题并创建对话。

创建请求只接受：

```json
{
  "challenge_slug": "reincarnation-trials",
  "persona_slug": "rogue-cultivator",
  "title": "可选标题"
}
```

Character、Scenario、Prompt、WorldBook 和奖励规则由后端根据 Manifest 固定，前端不能提交对应 ID。

长期玩法的列表项由公开 Runtime 标记为 campaign。开始时先创建长期存档，再为它创建唯一的持续 Conversation；普通单局挑战仍直接创建 Conversation。

## 长期存档

- Campaign 固定挑战版本、内容哈希、玩家人设和服务端随机种子。
- 一个 Campaign 最多绑定一个持续 Conversation；归档后恢复同一个对话，不创建章节或替代对话。
- 每个可信领域动作提交 expected revision 和幂等 action ID；重试不重复结算，并发旧请求不会覆盖新事实。
- 玩家只能查看自己的存档、对话和 player 可见事件；模型与内部事件不会进入普通 API。
- 放弃存档是带审计事件的生命周期动作。完成、死亡和后续转世规则由可信玩法服务处理。

## 对话操作

### 列表与状态

玩家只能列出自己的对话，可按状态和标题搜索。状态含义：

- `active`：允许发送、编辑、续写、重新生成和判定。
- `ended`：已经手动结束或完成结算，只读，不可恢复。
- `archived`：由玩家归档或玩法版本退役自动封存，只读；仍可浏览，只有仍绑定当前版本的手动归档对话才可恢复为 active。
- `deleted`：软删除，默认列表不展示。

### 消息与生成

- 发送用户消息并流式接收模型叙事。
- 在 Runtime 开放能力且目标分支没有已提交领域副作用时，编辑用户消息并重新生成后续内容。
- 重新生成最近回复或要求模型继续叙事。
- 生成期间使用对话级锁，避免同一对话并发生成。
- 取消连接不会授权其他用户接管生成。

### 状态与记忆

- 玩家可以查看经过 Runtime `visibility=player` 投影的当前状态与状态修订历史。
- 普通用户不能 PATCH 或整体替换状态；写接口仅管理员可用。
- 已封口旧回合由 Memory Worker 在后台异步归纳，不阻塞当前叙事；玩家不能生成、编辑或重试长期记忆。
- 玩家可以查看自己的上下文构建信息，也可以在左侧角色栏只读询问当前状态、任务、活动和已发生事件。
- 长期记忆、世界书命中、询问历史和上下文日志始终属于当前对话，不能作为判定或奖励资格。

### 消息改写、重新生成与平台能力

消息改写和重新生成共享同一项平台级能力，不属于任何玩法 Runtime。所有玩法默认使用统一的“剧情改写”策略、文案和全局奖励额度；玩法包不得通过 JSON 开关、改名或配置成本来授权或禁用该能力。平台策略由后端统一维护，前端只读取服务端公开的能力描述与奖励余额。

玩家发起重新生成或改写时，后端重新校验对话归属、active 状态、消息类型、平台策略、奖励余额和目标之后是否存在已提交 Campaign 动作或事件。扣除奖励、创建新分支、失效旧分支回合/消息/记忆并写入新的用户消息在同一事务中完成，任一步失败都会整体回滚。前端只负责展示能力和余额，不能自行认定免费、修改成本或扣减奖励。

## 判定系统

模型在需要不确定结果时提交 `roll_request`，后端负责：

- 读取管理员设置的全局开关与难度。
- 用模型提交的稳定 key 读取挑战 Runtime 中的类别、基础概率、骰面、收益和状态效果；模型不能覆盖这些参数。
- 使用服务端状态计算属性和特质修正。
- 对服务端规则提供的情境枚举精确查表。
- 应用高收益成功率上限和历史调整。
- 使用安全随机源执行判定，并原子持久化流水、结果消息和状态效果。
- 再次调用模型，让叙事服从真实判定结果。

用户不能从请求中关闭判定系统或指定 easy/normal/hard。

## 结局与奖励

模型通过 `complete_challenge` 提交版本中存在的稳定 `outcome_key` 和叙事摘要，不能提交奖励 key、数量、倍率或余额。Outcome 使用 `success`、`failure`、`neutral` 分类，展示标题和文案可以随版本调整，可信规则始终引用稳定 key。

后端根据对话固定的挑战版本重建持久化状态、服务端判定和回合等证据，调用该版本声明的 verifier；验证通过后，再由受信任 calculator 计算全部奖励。挑战流水、奖励余额、不可变账本、奖励快照和对话结束在同一事务完成；同一对话不能重复结算。验证条件不满足属于正常业务拒绝，不应按系统故障记录。

奖励定义是平台级资产，支持货币、物品、徽章、权益和额度。玩家可以在奖励页查看余额、藏品及流水；玩法可以把某项奖励作为另一玩法或功能的入口前置条件，但真正检查必须由后端执行。

“百年飞升劫”的三条路线和具体倍率见 `14-ascension-trial-gameplay.md`；两个内置修仙玩法的共享世界设定与独立运行边界见 `20-cultivation-shared-setting.md`。

## 用户设置

LLM 接入支持两种管理员可控模式，配置不另建公共表：`user_managed`（默认）由每个用户独立维护 Base URL、API Key、协议、模型和生成参数；`platform_managed` 由管理员在单例 `system_settings` 中维护公共连接、密文 API Key、协议、叙事模型及可选的 Memory/Inquiry 模型，所有用户统一使用。切回用户模式不会删除用户原配置。协议默认使用 `responses`，也可选择 `chat_completions`；Memory/Inquiry 模型为空时继承叙事模型。新设置默认使用 128000 上下文和 16384 最大输出 Token，设置接口拒绝上下文小于 4096、大于 2000000，回复小于 128，以及回复预留加 256 Token 后不小于上下文窗口。API Key 使用 `AUTH_DATA_ENCRYPTION_KEY` 做 AES-GCM 加密，接口和日志只返回是否已配置；平台模式必须具备公共 Base URL、Key 和叙事模型。

用户 LLM 设置不会改变平台 Prompt、世界书、判定算法或奖励规则。

## 对话分享

玩家只能从对话页头打开分享对话框。一次分享可以选择当前有效分支的全部展示消息，或用起点和终点选择一段连续消息；不支持离散多选，也不在单条消息上提供分享入口。服务端只接受已提交回合的玩家可见消息，单份快照最多 500 条、2 MiB。

公开链接是一份创建时冻结的只读快照，不会跟随后续生成、改写、状态变化或 Campaign 变化。玩家可设置独立标题、选择匿名或显示账号名称与头像，以及 7 天、30 天或永久有效期。首页“我的对话 / 我的分享”小标签中的“我的分享”跨对话分页展示当前用户的全部分享，可按状态筛选或按分享标题、来源对话标题搜索，并支持复制、浏览、撤销或重新发布并原子替换旧链接。发布完成只显示站内成功提示，不调用操作系统分享面板。非匿名身份由后端从当前登录账号的 `display_name` 和头像生成，客户端不能自定义；匿名分享不公开名称或头像。公开内容不包含其他账号资料、内部 ID、reasoning、工具记录、Memory、State、Campaign 私密字段、LLM Base URL、模型设置或 API Key。

匿名阅读页不要求登录，不初始化认证、不连接 WebSocket，也不能执行生成或玩法动作。分享所有者可以查看自己的分享记录；管理员可以查看摘要、处理举报和下架分享，治理操作写入审计事件。撤销、过期、管理员下架、对话软删除或账号物理删除后，公开读取统一表现为分享不存在或已失效。

## 管理员能力

### 用户与权限

- 管理端展示用户、角色和账号状态。
- 只有 `owner` 可以授予/撤销 `admin`、转交 owner 或停用管理员。
- `admin` 只能使用日常运营能力；平台认证策略、平台 LLM 密钥和角色管理属于 owner-only 操作。
- 安装完成、角色变更和账号停用写入脱敏管理员审计记录。

### 平台判定设置

- 开启或关闭天命判定系统。
- 设置 easy、normal 或 hard 难度。
- 设置对所有玩家生效，普通用户没有写权限。

### 挑战包

- 创建稳定 slug、名称和描述。
- 新挑战初始为 hidden，没有发布版本时普通用户不可见。
- 当前版本发布后挑战变为 active。

### 内置内容导入

- 查看仓库内置挑战的源版本、数据库当前版本、内容哈希和导入状态。
- 按 slug 显式导入可用版本，并走与手工发布相同的领域校验。
- 仓库内容与数据库当前快照不一致时，管理员可二次确认“覆盖现有内容”；普通导入请求不能隐式覆盖或降级。
- 已投入使用的内容更新必须提升版本号并发布新快照；新版本发布后，旧版本的普通 active 对话自动封存为只读，历史消息仍可浏览。用户可通过“基于新版本继续”创建绑定当前版本的新对话；不执行任意状态迁移。
- 导入接口不接受任意文件路径、Prompt 正文或客户端上传的版本文档。

### 挑战版本

- 为挑战包创建指定版本号的草稿。
- 有当前版本时，新草稿复制其 Manifest、资产和奖励规则，并更新 Manifest 版本号。
- 使用结构化分区编辑基本信息、入口资产、叙事资产、Runtime、State Schema、玩家界面、Outcome 与奖励规则。
- 高级 JSON 仅用于完整版本文档的导入、导出和高级维护，不是主要编辑入口。
- 发布前执行引用、Runtime 模块、状态权限、核心 Prompt、安全分段、世界书、Outcome、calculator 和奖励规则校验。
- 已发布版本只读，不允许原地修改。

### 玩法能力与奖励定义

- 查看后端已安装的 gameplay engine、动作、verifier、calculator 和 settlement handler。
- 维护平台级奖励定义；稳定 key 的类型、堆叠和消费语义一旦被玩法引用便不能原地改变。
- 挑战版本只能选择服务端注册的可信能力，不能上传可执行脚本、SQL 或任意表达式。

## 禁止能力

普通用户页面和 API 均不提供：

- Character、Persona、Scenario 的自由 CRUD。
- Prompt 或 PromptSegment 的读取与编辑。
- WorldBook 或条目的读取、绑定和编辑。
- 预设包文件操作。
- 挑战版本完整文档读取。
- 对话挑战版本、哈希或资产 ID 修改。
- 奖励金额、判定难度或判定结果修改。

仅隐藏前端入口不构成权限控制，以上边界必须由路由中间件和领域服务同时保证。

## 关键验收场景

1. 普通用户请求任何 `/api/admin/*` 路由得到 403。
2. 用户使用其他人的对话、消息、角色询问或上下文 UUID 时得到 404。
3. 用户 PATCH 对话时只能改变标题，提交技术字段不会生效。
4. ended 对话不能通过归档和恢复重新变为 active。
5. 已发布挑战内容被直接篡改后，运行时哈希校验阻止继续生成。
6. 相同对话重复提交完成动作时，只能产生一条 `challenge_run`，奖励账本不能重复入账。
7. 邮箱注册关闭时仍展示入口，但提交会得到管理员未开放的提示。
8. 管理员发布新版本后，旧版本普通 active 对话自动封存为只读并仍使用原版本；通过 fork 创建的新对话使用当前版本。

## LLM 请求路由（客户端直连）

两个开关互相独立，各管一件事：`llm_access_mode`（公共 LLM）决定“服务端转发”用谁的 Key（`platform_managed` 用平台 Key，`user_managed` 用用户自己的 Key）；“允许用户选择客户端直连”（`system_settings.client_llm_route_enabled`，默认关闭，只有 owner 可改）决定是否在服务端选项之外，额外给用户一个“客户端直连”选项。对话和 Campaign 固化的仍然只有 `server` / `client` 两种路由，`server` 具体用平台 Key 还是用户 Key 由接入模式在运行时决定。

| 公共 LLM | 直连开关 | 用户可选项 | 说明 |
| --- | --- | --- | --- |
| 关（`user_managed`） | 关 | 无（只有自带 Key 服务端转发） | 有效路由恒为 `server` |
| 关 | 开 | **服务端转发（推荐）** / 客户端直连 | 用户个人配置 + 服务端加密 Key，或个人配置 + 浏览器本地 Key |
| 开（`platform_managed`） | 关 | 无（只有平台模型） | 有效路由恒为 `server`，用平台 Key 与平台配置 |
| 开 | 开 | **平台模型（推荐）** / 客户端直连 | 平台模型正常发放奖励；直连用用户自己的 Key，不消耗平台模型额度 |

典型用法：服务器在境内、访问不了境外服务时，平台用公共 LLM 在服务端提供国内模型（可信，照常发奖励），需要境外模型的用户自带 Key 走客户端直连（不计奖励）。

- `server` 路由：现状不变，完整享有奖励与挑战记录。
- `client` 路由：只提供核心对话玩法。挑战与 Campaign 照常结算展示但**不发放任何账号奖励**（`rewards_disabled_reason=client_llm_route`）；重新生成/改写**不消耗额度**；发给模型的完整提示词（含隐藏剧情信息）对玩家透明；API Key 只存浏览器本设备（按用户隔离，登出清除），服务端不接收、不存储。客户端直连永远只用用户个人配置（base_url、协议、模型与采样参数）。
- 路由在对话（及 Campaign）创建时固化，之后不可修改；另一路由的旧对话只读，必须新建对话。`user_managed` 下切换到直连会删除服务端 Key（切回需重填）；`platform_managed` 下切换不涉及服务端 Key。
- 关闭平台开关时：用户保存的 `client` 选择被忽略（不改写，重新开启后自动恢复）；有效路由按 `server` 计算；开关关闭期间创建的对象一律固化为 `server`；进行中的直连回合立即中断（`llm_relay_lost`），已有直连对话只读。`user_managed` 下用户需填写 API Key 才能使用服务端转发（本设备 Key 保留不清除）；`platform_managed` 下用户自动回到平台模型，无需填写 Key。
- 切换公共 LLM（开→关或关→开）不改变任何用户的有效路由，不中断 Relay 连接与客户端直连对话；`server` 路由的用户按新的接入模式使用对应 Key。

### 模型端点适配限制

1. 只有官方域名会自动适配。DeepSeek 两种协议都可用；使用 Chat 协议时记忆与角色问答不可用，需改用 Responses。通过自定义域名或中转站访问时后端不会提前拦截结构化输出，由上游返回错误；这类错误照常透出，不自动重试。
2. 暂不支持 Anthropic 线格式。填入 Anthropic 原生接口地址会由上游返回错误。许多中转站同时提供 OpenAI 兼容接口，使用其 OpenAI 兼容地址即可。
