# 14. 百年飞升劫玩法规格

内容基线：`reincarnation-trials 1.0.0`，可信模块 `cultivation.trial@2`。2026-10-09 完成本轮成长、时间、路线、准备与死亡规则更新。本地结果和真实环境待验项见 [25 核心玩法验证](25-core-gameplay-validation.md)；这不是 release 验收结论。

## 权威与模块边界

本玩法使用 Challenge 模式。固定版本的 `cultivation.trial_rules:life` 定义保存九阶成长、出身、传承、物价、历练、配方和路线配置；可信模块计算结果，通用内核负责动作、参数、随机、时间与资源边界。执行沿用 Challenge 原有事务，状态、事件、动作提交、终局与积分一起提交。

- `module_state` 是隐藏、受保护的模块状态；其中 `life` 使用 SchemaVersion 2。
- `gameplay` 是从状态生成的公开投影；模型不能通过状态工具改写。
- 模型仅能维护 `narrative.name`、`narrative.appearance`、`narrative.background` 等允许的叙事字段；人物描写不会增加资源、能力或飞升资格。
- 旧 `profile.*` 成长字段和自由 Roll 表已删除。历史上出现过同名成功判定，不能满足新一世的模块终局条件。
- `POST /api/conversations/:id/actions` 与模型工具共用动作契约；归属、版本、revision、分支和幂等由平台验证。

内容源位于 `backend/data/preset_packs/reincarnation-trials/`。`definitions/trial-rules.json` 是数值入口（包括难度修正，不读取全局天命难度或 roll_config），`runtime/` 是状态、动作、结算与呈现契约，Prompt 负责叙事，世界书负责设定。资产名中的 `v1` 是稳定 slug，不表示当前内容仍是旧规则。运行时读取 PostgreSQL 已发布快照；修改仓库文件或重启不会自动覆盖已有内容。

## 开局与循环

七个 Persona 有各自的普通灵石/灵草与属性修正。服务端生成 18～25 岁开局年龄，根骨、悟性、气运基础值在 55～75 之间，再应用出身偏移；开始时没有修行传承，也不会赠送高阶道具。药庐、山门和剑崖的三种真实传承途径分别影响成长或防护。

典型循环是：求法 → 历练谋生 → 准备材料 → 闭关与突破 → 评估时间、伤势和飞升路线。安全谋生可以消耗时间换取少量资源；探索、斗法和社交提供不同风险与业力后果。不要把所有行动改成必需随机判定，也不要把普通问答变成消耗时间的活动。

玩家自由表达意图，模型从当前工具和真实可用方案中选择。叙事解释本轮变化并提供当前有意义的方向；不能承诺面板或工具不支持的物资、夺舍、无限延寿和特殊事件。

## 可信动作

动作结果附带服务端生成的 `narrative_feedback`，包含执行前后 revision、实际变化、当前境界、修为、生命、伤势和寿元等核心。闭关结算成功只代表修为按规则增长，不代表圆满或突破；例如当前仍是凡人、进度 52/100 时，反馈和后续状态问答都应依据这一事实。突破不可用的原因以只读说明提供给模型，调用被拒绝时明确本调用未执行。回春丹与破境丹保留各自版本定义的身份和用途，购买疗伤药不产生突破收益。

突破判定失败仍属于已提交结算，反馈同时保留目标失败和材料、时间、生命、伤势的实际代价。普通生成与继续叙事读取最新事实；不会为了改善叙事重复执行动作。此保障用于减少正文与面板矛盾，没有新增每回合语义审核，也不保证模型永远不会说错。公共协议见 [19 Agent Tool Loop](19-agent-tool-loop.md)。

除标注“仅玩家”的动作，以下动作都可由玩家或模型调用。带选项的动作只接收版本目录中的 `key`，不接受自定义收益、成功率、波数、耗时或奖励金额。

| 动作 | 实际作用 |
| --- | --- |
| `trial.activity` | 按版本方案结算工作、探索、斗法、社交、求法和仙缘委托 |
| `trial.practice` | 消耗时间和灵石，按当前境界、属性与传承增加修为 |
| `trial.breakthrough` | 满修为、伤势低于 30、材料足够后尝试下一境界 |
| `trial.buy` / `trial.sell` | 按固定物价买入或半价卖出，受物品最低境界约束 |
| `trial.craft` | 消耗配方材料与时间，失败也损失材料 |
| `trial.consume` | 使用疗伤丹或有限延寿丹等合法消耗品 |
| `trial.rest` | 七日休整，恢复 35 生命并减轻 25 伤势 |
| `trial.wait` | 明确等待一年，不获得资源；寿元不足一年时在寿尽处终止 |
| `trial.affinity_seek` | 持有委托资格后消耗一次寻缘机会 |
| `trial.affinity_use`（仅玩家） | 消耗真实仙缘符，完成仙缘路线 |
| `trial.rift_search` | 付费探查可用裂缝 |
| `trial.rift_enter`（仅玩家） | 穿越已发现裂缝，准备物影响风险 |
| `trial.tribulation_begin`（仅玩家） | 校验资格、消耗准备并创建本次九波天劫 |
| `trial.tribulation_wave` | 结算本次天劫当前一波 |
| `trial.tribulation_retreat`（仅玩家） | 放弃本次天劫并进入恢复冷却 |
| `trial.pass_away`（仅玩家） | 剩余寿元不超过五年时主动坐化 |

预览与执行共用可用方案计算，显示具体资源、时间和风险。后端仍会再次校验，按钮显示不能替代权限判断。

## 成长、时间与资源

两包共享九阶 key 和寿元基线，见 [20 共同设定](20-cultivation-shared-setting.md)。凡人、练气、筑基、结丹、元婴、化神、炼虚、合体、大乘的寿元分别为 80、120、200、500、1000、2000、5000、10000、20000 年；飞升门槛各自独立。

单局修为范围为 0～100。当前版本闭关基础进度为 23，传承和属性参与修正；每阶成本与天数从版本配置读取。突破失败损失 20 进度、15 生命并增加 10 伤势；疗伤丹恢复生命，不等同于消除伤势。生命、伤势、业力和资源都只能由可信动作修改。

时间只有一套累计整数分钟。年龄、寿元上限和剩余时间由出生年龄、境界、已用延寿丹和累计时间派生，不再让模型同时维护三组数值。动作先支付成本并推进时间，再结算收益；触及寿尽边界时截断到真实剩余分钟，不能先突破延寿、获得战利品或吃延寿丹再躲过死亡。普通聊天、查看、重连和重复读取不推进时间。

延寿丹每世最多三枚，每枚十年。跨越高阶寿元时仍受内核累计时间上限保护；内核当前累计上限为 1000 亿分钟，单次动作最多 100 万分钟，不能通过放宽单次动作制造无界工作。

灵石是局内交易资源，与账号积分分离。物品种类固定为灵石、灵草、突破丹、疗伤丹、延寿丹、雷符、护体法宝、定空锚；价格、最低境界、来源与消耗由版本配置决定。安全谋生的时间成本、付费准备、失败损耗和有限机会构成经济约束。旧的“所有灵石收益都必须掷骰”及独立全局定价表已被版本化规则替代。

## 三条飞升路线

| 路线 | 核心门槛与操作 | 固定账号积分 |
| --- | --- | ---: |
| 仙缘 | 结丹起，完成一次真实仙缘委托；每世最多两次付费寻缘；得到仙缘符后由玩家使用 | 150 |
| 虚空 | 元婴起，先发现可用裂缝，再由玩家穿越；定空锚自动消耗并提高成功率、降低失败损失 | 200 |
| 正统 | 化神起且修为圆满、生命至少 60、伤势低于 30、冷却结束；消耗灵石和护体法宝后发起九波天劫 | 300 |

仙缘资格、寻缘次数、获得仙缘符、使用仙缘符分别保存。获得符不会自动飞升，寻缘失败也消耗机会；机会用尽后可选择其他路线。裂缝穿越失败会关闭裂缝、造成生命和伤势损失并进入冷却，必须重新准备和探查。

九波天劫按肉身、神魂、道心分成三个阶段，每波成功才前进。失败保持当前波并增加后续灵石成本；严重失败额外受伤。每三波阶段最多消耗一张雷符，重复尝试同阶段不会反复扣符。雷符减少失败伤害与伤势，护体法宝减伤，境界、业力、伤势影响判定。撤退增加伤势并进入冷却，下次引劫从第一波重来；不同尝试的成功波不能拼接。当前版本冷却为 90 天。

这套九波机制只属于单局。长期 Campaign 的最终渡劫是独立遭遇，不复用单局波次。

## 死亡、结算与恢复

`peaceful_passing`、`lifespan_exhausted`、`perished` 分别表示主动坐化、自然寿尽和其他陨落，均为零积分。真实死因另记为寿尽、主动、斗法、雷劫或虚空裂缝。不得将任意失败统一描述为寿元耗尽。

三条成功路线由模块终态触发原平台结算；模型不能选择任意 outcome 或提交金额。客户端直连仍执行玩法和结局，但不发玩法积分。改写恢复当前分支的模块事实，已入账记录不回滚，也不能重复领同一局奖励，协议见 [21 积分](21-campaign-outcome-rewards.md)和 [24 架构](24-gameplay-module-architecture.md)。

## 配置与维护

后台“规则定义”按模块 Schema 编辑成长、七种出身、三种传承、历练、配方、物品价格和路线。发布会拒绝缺少必要动作、错误 Persona 映射、无普通谋生来源、非法资源、过量仙缘次数、给死亡结局配分或模型拥有关键状态等配置。

修改数值时同步检查动作预览、Prompt 和世界书的文字承诺；准确数值以定义和工具结果为准。与旧算法不兼容的改变需要新的模块版本与内容版本，不保留旧状态旁路。新的内置内容只用于空库初始化或管理员显式导入；本轮没有导入、发布或迁移真实环境。

当前离线模拟覆盖 166 局，包括三种难度、三条路线、全部出身以及准备充分/不足对照。样本成功率是特定策略的证据，不能代表真实玩家通关率、模型成本或叙事质量。详细分布、复现命令和维护者真实试玩清单见 [25 验证记录](25-core-gameplay-validation.md)。


## 提前终止

新增玩家专属 `trial.abandon` 与 neutral 零积分 `abandoned`，雷劫中也可用。提前终止不表示死亡、不推进时间、不将资源换成积分。`trial.pass_away` 与 `peaceful_passing` 仍要求剩余寿元不超过五年；聊天意愿通过通用提议工具转为界面确认。 完整协议见 [26 玩法结局生命周期](26-gameplay-ending-lifecycle.md)。
