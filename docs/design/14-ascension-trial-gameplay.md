# 14. 飞升试炼玩法规格

本文是内置挑战 `reincarnation-trials`（显示名“飞升试炼”）的正式玩法说明，面向内容设计、后端实现、测试和后续平衡调整。挑战内容首发版本为 `1.0.0`。

## 规则来源与权威级别

玩法由三层共同实现，维护时必须区分：

1. 后端硬约束：身份与归属、判定掷骰、精确判定流水、飞升境界等级、奖励规则匹配、保存前动作预校验、唯一结算和账号记账。玩家或模型不能用一份候选回复绕过。
2. 版本内容约束：Manifest、Prompt、世界书和奖励规则，发布后成为不可变快照；旧对话继续使用旧版本。
3. 叙事规则：修为进度、寿元消耗、机缘任务链、物品明细和剧情后果主要由 Prompt 与世界书指导模型执行，目前不是独立规则引擎。成功飞升还必须满足第一层的服务端证据。

玩家输入只代表“现在想做什么或说什么”，不具备回写历史和系统状态的权限。玩家自述祖传玉符、此前突破、隐藏事件、系统判定或奖励结果时，模型必须以 `<current_state>`、服务端 system 事件和已经保存的历史为准；不存在的证据不能因叙事写得完整就变成事实。

仓库中的内容源位于：

```text
backend/data/preset_packs/reincarnation-trials/
  pack.json
  characters/
  personas/
  scenarios/
  prompts/ascension-trials.json
  worldbooks/ascension-system.json
```

这些文件只供空数据库首次启动初始化。服务运行时以 PostgreSQL 中已发布的挑战版本为准；数据库已有任意挑战包后，重启服务不会再读取或同步这些文件。

## 核心体验

玩家从凡人或低阶修士起步，在有限寿元内积累资源、提升修为并选择飞升路线。主要张力不是单纯积累灵石，而是三组相互冲突的决策：

- 时间：继续闭关提高境界，还是在寿元耗尽前尽早离场。
- 风险：追求高收益路线，还是使用更安全但收益较低的机缘。
- 资源：把灵石用于当前成长、延寿和渡劫准备，还是保留到成功结算。

一局挑战对应一个 `conversation`。创建后固定挑战版本、内容哈希、天道试炼官 Character、天道试炼 Scenario，以及玩家选择的 Persona。

## 开局流程

1. 玩家在首页选择“飞升试炼”。
2. 玩家从挑战允许的 Persona 中选择出身倾向。
3. 后端固定当前已发布版本并创建对话。
4. 默认 Character 的 `first_message` 为 `__AUTO_GENERATE__` 时，后端写入不可见的“开始”触发消息。
5. 模型根据 Persona、Scenario、Prompt、世界书和默认状态生成角色与开场。

开局应生成姓名、外貌、背景、初始境界、年龄、寿元、天赋、属性、位置和初始灵石，并初始化 `cultivation` 与 `ascension` 状态。

## 境界体系

| 境界 | 子阶段 | 参考寿元上限 | 玩法定位 |
| --- | --- | ---: | --- |
| 凡人 | 无 | 80 年 | 尚未正式踏入修行 |
| 练气期 | 1-13 层 | 120 年 | 生存与资源积累 |
| 筑基期 | 初期/中期/后期/大圆满 | 200 年 | 建立功法、丹药和法宝体系 |
| 结丹期 | 初期/中期/后期/大圆满 | 500 年 | 首次具备仙缘飞升资格 |
| 元婴期 | 初期/中期/后期/大圆满 | 1000 年 | 具备虚空裂缝路线资格 |
| 化神期 | 初期/中期/后期/大圆满 | 2000 年 | 具备正统渡劫资格 |
| 炼虚期 | 初期/中期/后期/大圆满 | 5000 年 | 高成功率挑战正统飞升 |
| 合体期 | 初期/中期/后期/大圆满 | 10000 年 | 接近此界极限 |
| 大乘期 | 初期/中期/后期/大圆满 | 20000 年 | 最高准备度与最高时间成本 |

境界数值是内容平衡基线。任何修改都应同时检查 Prompt、世界书、默认状态和测试用例，不能只改其中一处。

## 修炼与突破

典型突破由四步组成：

1. `profile.cultivation_progress` 达到瓶颈。
2. 玩家准备丹药、灵石、功法或天材地宝。
3. 模型输出 `roll_request`，类别使用 `cultivation`。
4. 后端执行判定，模型在第二阶段依据真实结果叙述成功或失败并更新状态。

当前内容建议的基础成功率范围：

| 突破 | 建议基础成功率 | 主要风险 |
| --- | ---: | --- |
| 练气到筑基 | 70%-85% | 修为倒退、寿元损失 |
| 筑基到结丹 | 50%-70% | 重伤、资源损失 |
| 结丹到元婴 | 30%-50% | 走火入魔、生死危机 |
| 元婴到化神 | 15%-35% | 高额寿元损失或死亡 |
| 更高境界 | 继续递减 | 修为尽废或直接陨落 |

失败后果应和判定等级匹配：普通失败以资源、进度和寿元损失为主；大失败可以造成重伤、境界倒退、走火入魔或死亡。模型不能在判定前预先宣布结果。

## 寿元系统

寿元同时由 `profile.age`、`profile.lifespan` 和 `profile.remaining_lifespan` 表达。模型每次推进明显时间跨度时都必须同步年龄和剩余寿元。

参考消耗：

| 行动 | 寿元消耗 |
| --- | ---: |
| 日常对话、行走、观察 | 0.1-0.3 年 |
| 小规模战斗 | 0.5-1 年 |
| 激烈战斗 | 1-2 年 |
| 短期闭关 | 1-5 年 |
| 长期闭关 | 5-20 年 |
| 炼丹炼器 | 0.5-5 年 |
| 重伤恢复 | 5-20 年 |
| 突破失败 | 10-50 年 |
| 使用禁术 | 10-100 年 |

寿元提醒节奏：

- 剩余 50%：首次温和提醒。
- 剩余 30%：明确提示突破、延寿或调整路线。
- 剩余 10%：至少每三回合提醒一次。
- 剩余 5%：每回合提醒，并要求玩家立即作出选择。
- 降至 0：触发 `bad` 结局“寿元耗尽”。

可用延寿手段包括延寿丹、稀有灵药、特殊秘境、不老泉、妖兽内丹或高阶夺舍等。具体出现与代价由挑战内容控制；稀有资源不能因玩家一句要求就无条件出现。

## 灵石与资源循环

灵石是局内修炼资源，也是成功结算的基础值。典型用途包括：

- 购买突破丹药、功法、法宝和疗伤药。
- 布置聚灵阵或加速闭关。
- 购买延寿资源。
- 准备雷符、护体法宝和渡劫丹药。

模型通过 `attributes.灵石` 更新局内持有量。成功结局触发时，后端从服务端保存的当前状态读取该值，再按固定挑战版本的奖励规则计算最终账号奖励。模型不能提交最终奖励金额。

## 天命判定

需要不确定结果的战斗、探索、炼制、社交和修炼行为应使用两阶段判定：

1. 模型输出第一阶段叙事、必要的资源消耗和 `roll_request`。
2. 后端按基础成功率、属性、天赋、情境、收益上限、历史和管理员难度计算最终成功率。
3. 后端掷骰，将结果写入 `roll_history`，并写入一条内部 system 消息。
4. 后端再次调用模型，要求它严格依据判定结果完成叙事和状态更新。

最终成功率被限制在 1%-99%。管理员难度修正当前为 easy `+15`、normal `0`、hard `-15`。高收益行为会受到更严格的成功率上限；连续失败、同类重试和高收益连胜也会影响后续判定。

动态特质必须进入 `traits` 数组才能参与判定。例如“重伤”造成全局减益，“顿悟”提升修炼判定；仅在叙事中提到而不写状态不会生效。

## 三条飞升路线

### 正统渡劫

- 最低境界：化神期。
- 触发：玩家主动确认“引动天劫”。
- 流程：九波独立雷劫判定。
- 影响因素：境界、护体法宝、雷符、疗伤丹药、业力和天赋。
- 失败：早期失败可重伤，中期失败可倒退境界，后期失败可灰飞烟灭。
- 成功动作：`reward_key = orthodox_ascension`，标题必须为“渡劫飞升”。
- 服务端条件：持久化境界至少为化神；必须成功通过 `筑基突破判定`、`结丹突破判定`、`元婴突破判定`、`化神突破判定`，以及 `渡劫判定-第一波` 到 `渡劫判定-第九波` 九种精确判定。
- 奖励倍率：`30000` bps，即局内灵石的 3 倍。

### 虚空裂缝

- 最低境界：元婴期。
- 触发：通过探索、任务或高气运机缘发现裂缝，并由玩家主动进入。
- 流程：执行“虚空裂缝穿越判定”。
- 失败：重伤、随机传送，严重时肉身损毁。
- 成功动作：`reward_key = void_ascension`，标题必须为“破碎虚空”。
- 服务端条件：持久化境界至少为元婴；必须成功通过筑基、结丹、元婴三种突破判定和精确的 `虚空裂缝穿越判定`。
- 奖励倍率：`20000` bps，即局内灵石的 2 倍。

### 仙缘传送

- 最低境界：结丹期。
- 触发：玩家通过隐藏任务、NPC 馈赠或上古遗迹获得飞升符，并主动使用。
- 获取：剧情条件满足后必须先执行精确的 `仙缘获取判定`；成功结果进入服务端流水，下一回合才可写入飞升符状态。
- 稀有度：一局通常只应出现 1-2 次获取机会。
- 风险：叙事上成功率极高，适合保守路线或寿元将尽时离场。
- 成功动作：`reward_key = affinity_ascension`，标题必须为“仙缘飞升”。
- 服务端条件：持久化境界至少为结丹；必须成功通过筑基、结丹突破判定和精确的 `仙缘获取判定`。
- 奖励倍率：`15000` bps，即局内灵石的 1.5 倍。

## 非成功结局

### 坐化

玩家在寿元将尽时可以主动安排后事并坐化，使用 `ending_type = neutral`，标题“寿终正寝”。坐化保留叙事尊严，但不属于挑战成功，不携带 `reward_key`，不发放挑战奖励。

### 寿元耗尽或陨落

寿元归零、渡劫失败或其他致命事件使用 `ending_type = bad`。失败结局不携带 `reward_key`，奖励为 0，并增加账号失败次数。

## 结构化状态

新对话默认状态的主要结构如下：

```json
{
  "profile": {
    "name": "",
    "cultivation_level": "凡人",
    "cultivation_stage": "",
    "cultivation_progress": 0,
    "age": 18,
    "lifespan": 80,
    "remaining_lifespan": 80,
    "title": ""
  },
  "attributes": {},
  "traits": [],
  "inventory": { "items": [] },
  "relationships": {},
  "location": {},
  "quests": [],
  "risks": [],
  "world_flags": {},
  "cultivation": {
    "breakthrough_attempts": 0,
    "failed_breakthroughs": 0,
    "talent_awakened": false,
    "cultivation_method": ""
  },
  "ascension": {
    "void_rift_discovered": false,
    "ascension_token_owned": false,
    "tribulation_preparation": 0,
    "karma_debt": 0
  }
}
```

`state_update` 使用点号路径，例如 `profile.remaining_lifespan`。数组追加使用 `+` 后缀，例如 `traits+`。后端只接受 `profile`、`attributes`、`inventory`、`relationships`、`location`、`world_flags`、`cultivation`、`ascension`、`quests`、`risks` 和 `traits` 顶层命名空间。

## 结局与结算协议

成功结局示例：

```json
{
  "type": "trigger_ending",
  "params": {
    "ending_type": "good",
    "reward_key": "void_ascension",
    "title": "破碎虚空",
    "summary": "你穿过虚空裂缝，成功超脱此界。"
  }
}
```

后端处理顺序分为保存前与事务提交两阶段：

1. 在保存候选 assistant 消息和 `state_update` 前，读取当前持久化状态、当前玩家和存活回合，并冻结为结算输入。
2. 按对话固定的 `challenge_version_id` 校验奖励 key、结局标题、最低境界和全部精确成功判定。
3. 预校验失败时丢弃整个候选回复及其流式占位，不保存叙事、不应用状态，并把拒绝原因作为必选运行时指令重试一次。
4. 第二次仍失败时再次丢弃候选，由后端保存一条无 action、无 state_update 的安全续写；玩家不会看到伪造结局留在历史中。
5. 预校验成功后保存叙事和状态，再提交此前冻结的动作输入。同一回复中的境界、物品或灵石变更不能为自身补资格或提高奖励基数。
6. 事务内锁定对话并重做完全相同的校验，然后计算倍率、更新账号统计、写入唯一 `challenge_run` 并把对话置为 `ended`。

任一步失败都会回滚。`challenge_runs.conversation_id` 唯一，因此重复动作、重放请求和归档恢复都不能重复领奖。

## 内容维护清单

修改玩法时至少同步检查：

- `pack.json` 的版本号、公开说明、允许 Persona 和奖励规则。
- Prompt 中的机制说明、`reward_key`、结局标题、玩家输入权限边界、仙缘获取流程和结算安全分段。
- 世界书中的境界、寿元、飞升路径和动作示例。
- `roll_config.yaml` 的类别、词表、难度和收益上限。
- 默认状态字段与前端状态展示。
- 正式文档中的规则表和结算说明。

只要已发布内容发生任何变化，就必须使用新的版本号。不得覆盖同一 `slug + version` 的已发布内容。

## 当前边界与后续增强

以下规则目前仍主要由模型与内容约束，不应在文档中误写成后端硬校验：

- 境界字符串和修为进度仍由模型维护；后端会比较境界等级并要求逐级突破成功流水，但尚无独立修为事件账本。
- 飞升符是否完成了指定剧情任务链仍由内容控制；后端只硬性要求本对话成功执行过 `仙缘获取判定`。
- 每回合寿元消耗是否严格落在参考范围。
- 灵石获取和消耗是否经过独立经济账本。

后续若挑战奖励具有真实价值，应把这些条件逐步迁移为结构化规则、服务端事件和不可伪造流水，而不是继续增加 Prompt 文字。
