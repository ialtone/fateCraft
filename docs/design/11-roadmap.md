# 11. 路线图与工程边界

路线图只记录当前实现之上的后续工作，不把已经完成的能力写成规划。每项只有在代码、数据库、管理流程、测试和文档同时满足验收条件后才算完成。

## 当前基线

项目当前已经具备：

- LinuxDo OAuth、可配置邮箱认证、user/admin 权限和服务端会话；
- PostgreSQL 挑战包、不可变发布版本、内容哈希、内置内容显式导入和多奖励账本；
- 单局 Challenge 与长期 Campaign 两种 Runtime 模式；
- 题材无关的 State Schema、Presentation、判定、Outcome、奖励和 Campaign 动作注册表；
- 主叙事普通文本 + 真实 Agent Tool Loop，同时适配 Chat Completions 与 Responses；
- 工具快照、调用幂等、短事务、`partial` attempt 和进程重启恢复；
- 原生 JSON Schema 的异步 Memory Agent 与独立只读 Character Inquiry Agent；
- 128K/16K 默认窗口、完整回合预算、Campaign Projection 压缩和上下文审计；
- 显式模型诊断与默认关闭的详细 LLM 请求日志；
- 修仙长期玩法的角色、功法、物品、制作、市场、地图、NPC、势力、事件、任务、遭遇和结局系统。

当前架构不依赖历史数据库迁移。Schema 变化直接更新 `backend/scripts/sql/init.sql`，开发和测试环境重建空库。

## P0：协议与事务回归

### Provider 兼容矩阵

维护 Chat Completions / Responses × stream / non-stream 的固定回归，覆盖文本、工具、参数分片、拒答、空响应、EOF、截断、超时、429、5xx 和不规范兼容端点。

验收：适配层始终产出同一内部事件语义；任何不完整步骤都不会执行工具或保存临时文本；响应体交付前的临时传输错误可有限重试，但模型步骤不会因解析或工具结果而重放，也不会切换协议。

### 工具原子性

持续补充真实 PostgreSQL 测试，覆盖：

- committed 领域事实、invocation、tool 消息与 attempt 计数同事务；
- rejected/failed Handler 即使已经触碰仓储也不留下领域写入；
- call ID 重放、参数哈希冲突、revision 冲突和第 7 个写工具；
- 写工具后模型失败进入 partial，继续叙事不重放旧工具；
- 进程退出后 received invocation 变为 abandoned，committed 工具保持有效。

验收：数据库故障和进程中断不能制造“领域已变但审计未提交”或重复副作用。

## P1：内容管理可维护性

### 版本差异与发布报告

- 展示草稿与当前发布版本的 Manifest、Runtime、资产、定义、Outcome 和奖励差异；
- 发布校验按字段和资源返回结构化错误；
- 发布确认页突出工具权限、State Schema、安全 Prompt、奖励和 Persona 范围变化；
- 保存发布者、发布时间、哈希和可读变更说明。

验收：维护者能在发布前明确回答哪些玩家规则、模型工具和结算条件发生变化。

### 玩法包校验工具

- 为稳定 key、跨定义引用、动作可达性和资源闭环提供离线校验命令；
- 提供 Prompt 核心段和工具语义检查；
- 对大 Projection、能力目录和世界书执行 token/字节预算报告；
- 保留完整 JSON 导入导出作为管理员高级入口。

## P1：前端与可观测性

### 浏览器端回归

当前自动化前端基线是类型检查、格式检查和生产构建，尚无完整浏览器 E2E。后续优先覆盖：

- Agent 文本流、工具活动和 partial 提示；
- WebSocket 断线重连、sequence 缺口与 REST 恢复；
- Campaign 多页签、revision 冲突和移动端布局；
- Memory 状态、角色问答取消和快照过时；
- 管理员发布、覆盖确认和模型诊断。

### 指标与诊断

- 指标区分模型步骤、工具执行、业务拒绝、partial attempt 和最终完成；
- 统计每回合模型步骤数、写工具数、token、延迟和 Provider 错误；
- 为事务失败、重复异常工具调用、Memory 积压和费用突增配置告警；
- 详细请求日志继续由管理员显式开启，并保持认证信息脱敏。

## 长期备忘：全新核心玩法模块

现有 `campaign.generic@1` 适合组合通用世界、经济和任务能力。卡牌构筑、城市经营、推理解谜、生存制作、战棋策略等拥有独立状态和结算循环的玩法，需要新的可信服务端模块，不能仅通过配置启用。该方向仅在未来有明确需求时评估，不构成当前迭代承诺。

候选方向、模块边界规则、管理端、前端和落地验收参考见 [未来玩法方向](future-gameplay-directions.md)。

## P2：平台安全与运营

- 邮箱密码重置、设备会话和 OAuth 绑定安全流程；
- 登录、生成、角色问答和管理员发布的持久限流；
- 用户 LLM API Key 的信封加密和主密钥轮换；
- PostgreSQL 自动备份、异地副本和隔离恢复演练；
- 挑战下架、版本使用量和运行成本统计。

## 暂不进入核心范围

- 普通用户自由编辑技术 Prompt、世界书、Character 或 Scenario；
- 把已发布挑战版本恢复为可写草稿；
- 用自然语言、Memory 或角色问答直接授予状态、资源或奖励；
- 运行玩法包携带的任意脚本、SQL 或未隔离插件；
- 多人共享世界、玩家交易或 PvP；
- 未经预算和可见性约束的跨对话向量记忆。

若未来增加无奖励沙盒模式，应作为独立领域设计，不降低挑战与 Campaign 的权限、事务和结算边界。

## 完成定义

一个路线图条目完成时至少需要：

1. 数据模型、权限、失败和并发路径有明确定义。
2. 后端鉴权、事务与数据库约束已经实现。
3. 前端具备完整操作、加载、空数据、取消和错误状态。
4. 单元或集成测试覆盖主要成功、失败、越权和恢复路径。
5. 空库初始化、部署和故障恢复方式可执行。
6. 对应设计文档、玩法规格和 API 契约同步更新。
